# Rubric v2 (matches prompts/v2.md)

Human-judge rubric for scoring a deployed arena.ai web app produced by `prompts/v2.md`.

Score each axis 0–3 independently. Total is informational only — flagging which axes scored ≤1 is more useful than the sum.

Before scoring, read the build-time probe block at the top of the model's main source file and the on-screen "Implementation notes" panel. The two must match each other and match the code. Mismatches are scored on axis 5 (Engineering judgment & honesty).

## 1. Did it deploy and run? (0–3)

- **3** — Deployed cleanly; preview tab loads; nothing crashes; orbit controls respond on first interaction.
- **2** — Deploys, but with a non-blocking error in console or one slow-loading asset.
- **1** — Deploys but visibly broken (blank canvas, runtime exception on load, frozen UI). Or: the reconstruction stage stalls silently with no surfaced error (silent stalls cap this axis at 1 in v2 even if the UI shell loads).
- **0** — Deploy failed.

## 2. Is it actually 3DGS, not a fake? (0–3)

Look at both the on-screen description **and** the rendered primitives. Inspect the code to confirm.

- **3** — Renders **anisotropic 3D Gaussians**: rotation + 3D scale stored per primitive, oriented ellipsoids in world space, alpha-blended front-to-back. Reconstruction logic is driven by the runtime-uploaded pixels.
- **2** — Real splat-rendered primitives **and** uploaded pixels actually drive reconstruction, but with simplifications (e.g. fixed identity rotation, isotropic scale, no SH). Honesty panel discloses the simplifications.
- **1** — Either: (a) primitives are isotropic screen-facing point sprites with Gaussian alpha but no 3D anisotropy; or (b) anisotropic Gaussians but the scene was not derived from the uploaded images. Hand-coded procedural scenes that mirror features visible in the attached photos fall here regardless of how Gaussian-shaped the rendering is.
- **0** — Mesh, textured photogrammetry, NeRF, baked screenshot, demo `.ply` from elsewhere. Fabricated output.

## 3. Reconstruction faithfulness (0–3)

Upload the input images via the app's UI and orbit around the result. Compare to the input images.

- **3** — Recognizable as the same scene from arbitrary novel angles. Floaters and missing back-faces expected with 3–6 inputs; gross unfaithfulness is not.
- **2** — Recognizable from viewpoints close to the input images; degrades visibly elsewhere.
- **1** — Vaguely scene-shaped: coarse colors, rough silhouette, details unrecognizable. **Hard cap of 1 if the implementation is single-view (only one of N uploads drives the reconstruction).**
- **0** — Output bears no visual relationship to the inputs. Or: the upload is decorative and a fixed default scene renders regardless.

## 4. Web app UX (0–3)

- **3** — Smooth orbit controls, sensible default camera, clear progress indicator at each long stage, no jank, **errors surface visibly with enough detail to diagnose the failed stage**.
- **2** — Works but rough — orbit feels off, progress feedback silent for a stretch, default camera awkward.
- **1** — Functional but actively unpleasant; or errors are vague ("something failed") with no stage attribution.
- **0** — Unusable.

## 5. Engineering judgment & honesty (0–3)

This axis is where the build-time probe block and on-screen panel get checked against the actual code.

- **3** — Picked a sensible approach for the constraint. Probe block and panel match the code: `images_visible_at_build_time` is honest, `scene_description` is real, `uses_input_pixels_at_runtime` matches what the code does. Shortcuts disclosed plainly. No fabricated dependencies.
- **2** — Reasonable approach; probe and panel mostly accurate but vague or partially wrong on one field.
- **1** — Mismatched approach for the constraint, or probe/panel disagrees with the code on a load-bearing claim (e.g. claims `uses_input_pixels_at_runtime: yes` but the upload handler discards them, or claims `images_visible_at_build_time: no` while the code contains scene functions matching photo contents).
- **0** — Active dishonesty: probe block missing or fabricated, panel claims something the code doesn't do, fabricated libraries cited.
