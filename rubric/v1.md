# Rubric v1 (matches prompts/v1.md)

Human-judge rubric for scoring a deployed arena.ai web app produced by `prompts/v1.md`.

Score each axis 0–3 independently. Total is informational only — flagging which axes scored ≤1 is more useful than the sum.

## 1. Did it deploy and run? (0–3)

- **3** — arena.ai deployed cleanly; both preview tabs load; nothing crashes; orbit controls respond on first interaction.
- **2** — Deploys, but with a non-blocking error in console or one slow-loading asset.
- **1** — Deploys but visibly broken (blank canvas, runtime exception on load, frozen UI).
- **0** — Deploy failed.

## 2. Is it actually 3DGS, not a fake? (0–3)

Inspect both the on-screen description **and** what's actually rendering.

- **3** — Renders true 3D Gaussian splats: anisotropic, view-dependent, alpha-blended; you can see splat-shaped primitives if you zoom in. The data flow from input images → Gaussians is real.
- **2** — Renders Gaussian splats but the Gaussians weren't derived from the input images (e.g. a hard-coded demo scene with input images shown alongside, but not used). Or: an honest approximation explicitly labeled as such, where the rendering primitive is genuinely splat-based.
- **1** — Mesh, point cloud, or sprite-billboards masquerading as splats. Or: claims 3DGS in the text panel but renders something else.
- **0** — Static image, baked screenshot, NeRF, or unrelated content. Fabricated output.

A model that ships an honest approximation and labels it correctly should not score below 2 on this axis.

## 3. Reconstruction faithfulness (0–3)

Orbit around the scene and compare what you see to the input images.

- **3** — Recognizable as the same scene/object from arbitrary novel angles. Minor floaters and missing back-faces are expected with 3–6 input views.
- **2** — Recognizable from viewpoints close to the input images; degrades visibly elsewhere.
- **1** — Vaguely scene-shaped; coarse colors and rough silhouette; details unrecognizable.
- **0** — Output bears no visual relationship to the inputs.

## 4. Web app UX (0–3)

- **3** — Smooth orbit controls, sensible default camera, clear progress indicator while reconstructing, no jank.
- **2** — Works but rough — e.g. orbit controls feel off, progress feedback is silent for a stretch, default camera puts you inside the scene.
- **1** — Functional but actively unpleasant to use.
- **0** — Unusable interaction layer.

## 5. Engineering judgment & honesty (0–3)

Read the on-screen text panel and any visible code/comments.

- **3** — Picked a sensible approach for the constraint (e.g. feed-forward over from-scratch optimization given browser limits). Stated approach, libraries, and caveats clearly. No fabricated dependencies. Shortcuts disclosed.
- **2** — Reasonable approach; description present but vague or partially wrong.
- **1** — Approach mismatched to the constraint (e.g. attempted from-scratch WebGPU training that timed out without fallback). Caveats absent or misleading.
- **0** — Description claims something the code doesn't do. Fabricated libraries cited. Active dishonesty.

## Suggested reporting format for `observations/`

For each run, log:
- Model name + date.
- Image set used.
- Per-axis scores (1 through 5).
- Two-sentence summary of what the model actually did.
- One-sentence note on what (if anything) this run suggests about the next prompt version.
